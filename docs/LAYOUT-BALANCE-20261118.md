## 2. 중복 조작 전수 점검

홈 → 이야기 → 지도 → 활동 10개(탐구·주문 제작·새 의뢰) → 보고·코어·엔딩·인증서에서 보이는 조작 요소를 JS로 뽑아 비교했다(`report.json`의 `controls`).

| 화면 | 겹치던 것 | 처리 |
|---|---|---|
| 코어 재가동 | 「코어 레버」 밀기 막대와 「길게 눌러 코어 재가동」 버튼이 같은 일(레버 0→100%)을 함 | 밀기 막대를 없애고 주 버튼 하나만 남김. 안내 문장을 「아래 버튼을 길게 눌러 줘.」로 맞춤. 키보드는 버튼의 Enter·Space 길게 누르기로 그대로 |

점검했지만 그대로 둔 것(이유):

- 활동 위 「개념 보기」 단계와 마지막 주 버튼 「개념 보고 다음 활동」: 앞은 다시 보기(진행 안 함), 뒤는 다음 단계로 넘어감. 하는 일이 다르다.
- 우산·보관함 화면의 돋보기 끌기와 ＋/−/↺: 돋보기는 부분 확대 관찰, 버튼은 전체 크기와 키보드 접근용.
- S01·S10 「관찰 도움말」「시험 도움말」과 모루의 힌트: 도움말 안에 성취기준 관련 주의 문장(겉모습만으로 재료를 확정할 수 없음, 재료를 바꾸면 다시 시험)이 있다. 학습 문구라 옮기지 않았다.
- S03 2D 화면의 재료 카드 「바로 시험하기」와 손동작 버튼: 카드는 시료를 바꾸면서 시험, 손동작은 지금 시료 시험. 실험 흐름 설계(2026-11-17)라 유지.
- 의뢰 대화의 말풍선 누르기와 「이야기 더 듣기」: 글 버튼은 낮은 무게(text)로 이미 정리돼 있다.
- 설정의 「공방을 깨우는 이유 다시 보기」와 홈 「시작 이야기 보기」: 다른 화면에 하나씩.

### `check:layout` 스크립트 갱신 (2026-11-19 오후)

`tools/check-experience.py`를 지금 앱에 맞게 고쳤다.

- 단계 줄은 번호 대신 이름(「새 의뢰」·「개념 보기」·「주문 제작」)으로 찾는다. 주문 제작 화면(S02·S06·S08)은 단계가 하나 더 있어 번호가 밀린다.
- 새 의뢰는 고르는 즉시 채점된다. 문제는 ID 대신 화면별 순서로 고른다(현재 ID는 -a·-b·-c·-d가 섞여 있다).
- 주문 제작 화면 캡처를 추가했다.
- 개념 영상은 15초다. 움직임 줄이기에서는 재생 버튼을 누른다.
- 이야기는 홈의 「시작 이야기 보기」로, 지도 의뢰는 공방을 고른 뒤 「의뢰 이야기 보기」로 연다.
- 임시 파일은 `.tmp/check-experience`에 둔다.
- 터치 크기 하한은 프로젝트 기준인 44px로 맞췄다(이전 47px).

결과(305화면 × 5크기): 페이지 오류 0, 화면 넘침 0, 새 의뢰 20개 실제 조작 풀이 통과(분류는 포인터 끌기), S05 나무토막 끌기·S09 설계 놓기 통과, 학생 기록 오염 0.

개념 영상 아래 「n번째 장면」 버튼이 42px(915×412는 40px)라 44px 기준에 못 미쳤다(150건 = 3개 × 10편 × 5크기). 사용자 승인으로 `src/concept-focus.css`의 두 값을 44px로 올렸고, 다시 돌린 `check:layout`은 305화면·5크기에서 페이지 오류 0, 배치 지적 0, 넘침 0으로 통과했다(2026-11-19).
