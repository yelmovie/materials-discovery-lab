## 한 줄 요약

성질 시험실의 S03 「직접 시험해 증거를 모아라」를, 연구원이 시험 길을 걸어 다니며 시료를 직접 밟고 당기고 비추고 적셔 보는 3D 스테이지로 바꾼다.

## 바꿀 자리

- 물체와 물질 단원(4과05-01~03). 활동 S01~S10이 차례로 이어지고 모두 필수다.
- 대상은 성질 시험실(단단이)의 S03이다. 전체에서 3번째 활동이다.
- 파일: `src/screens/Activities.tsx`(72~97행 부근, `<Samples/>`), `src/domain/model.ts`(시료 조합 25~30행, 관찰 처리 157행, 완료 174행), `src/domain/challenges.ts`(의뢰 S03-a·S03-b). 화면은 `src/App.tsx` 184행 부근에서 `Activity`를 그린다.
- 이 프로젝트에는 물에 뜨는 성질을 다루는 활동이 없다. 처음 추천 때 적은 "나무 발판은 물에 뜬다"는 내용에 없으므로 쓰지 않는다.

## 지금 방식과 바뀐 방식

| | 지금 | 바꾼 뒤 |
|---|---|---|
| 실험 고르기 | 화면에서 실험 네 개 중 하나를 고른다 | 시험 길의 네 구역으로 걸어간다 |
| 당기기 | 시료를 옆으로 민다(swipe) | 시료 끈 앞에서 '당기기' 버튼을 누르고 있는다 |
| 손전등 | 누른다(tap) | 시료 판 앞에서 '비추기' 버튼을 누른다 |
| 스포이트 | 누르고 있는다(hold) | 시료 위에서 '물 떨어뜨리기' 버튼을 누른다 |
| 누르기 | 누르고 있는다(hold) | 시료 발판 위로 뛰어올라 밟는다 |
| 결과 고르기 | 결과 설명을 고른다 | 같다 |

이 프로젝트에서 점프가 직접 쓰이는 곳은 누르기 구역이다. 나머지 세 구역은 걸어가서 버튼으로 시험한다.

## 과학 개념과 조작

| 개념 | 달리기에서 하는 일 |
|---|---|
| 물질마다 성질이 다르다 | 같은 조작을 시료마다 해 보고 결과가 다른 것을 본다 |
| 눌렀을 때 모양이 변했다가 돌아오는 것과 그대로인 것이 있다 | 밟으면 고무 시료는 눌렸다가 돌아오고, 금속 시료는 그대로다 |
| 당겼을 때 늘어나는 것과 그렇지 않은 것이 있다 | 당기기 버튼을 누르는 동안 시료 끈이 늘어나거나 그대로다 |
| 빛이 통과하는 것과 그렇지 않은 것이 있다 | 비추면 판 뒤 벽에 빛이 닿거나 닿지 않는다 |
| 물이 스며드는 것과 그렇지 않은 것이 있다 | 물방울이 스며들거나 겉에 맺힌다 |

### 지켜야 할 제한

- `docs/screen-spec.json`의 `materialLimits`: "모든 물질에 대한 보편 법칙이 아닌 지정 시료의 수업용 관찰 모델", "시료의 눌림·복원 관찰은 … 실제 충격 완화나 안전을 보장하지 않음".
- 그래서 고무 발판이 캐릭터를 높이 튕겨 올리는 표현은 넣지 않는다. 밟으면 눌렸다가 돌아오는 모습만 보여 준다.
- 시험하는 시료와 조합은 `model.ts`의 지정 조합만 쓴다. 조합에 없는 시료를 길에 놓지 않는다.
- `requiredComparisons` 전체를 관찰해야 끝난다. 관찰 수를 줄이지 않는다.
- **S04와 S09가 S03의 관찰 기록을 근거로 연결해 쓴다**(`requiredLinks`, `model.ts` 31~32행). 관찰 id는 `실험:시료:standard` 형식 그대로 남겨야 한다. 형식이 달라지면 뒤 활동이 동작하지 않는다.

## 코스 구성

시험 길은 한 줄로 이어지고 구역 네 개가 차례로 나온다. 구역마다 지정 시료가 나란히 놓인다.

1. **누르기 구역:** 시료 발판을 하나씩 밟아 본다.
2. **당기기 구역:** 시료 끈을 하나씩 당겨 본다.
3. **비추기 구역:** 시료 판을 하나씩 비춰 본다.
4. **적시기 구역:** 시료 위에 물을 떨어뜨려 본다.
5. **단단이의 의뢰:** S03-a, S03-b를 기존 그대로 푼다.

시료 하나를 시험할 때마다 결과 설명을 고르고, 맞게 고르면 관찰 기록이 남는다. 구역 순서는 자유롭게 오갈 수 있게 길을 막지 않는다. 방해꾼은 지도 악당 스프라이트를 써서 구역 사이 통로를 오가게 한다.

- React 19 + Phaser 3.90 구조다. npm에 `three` 0.180.0이 이미 있지만 `src`에서 쓰는 곳은 없다. 달리기 화면은 React 컴포넌트 하나로 만들고 그 안에서 `import('three')`로 필요할 때 불러온다.

- `scripts/prepare-offline.mjs`가 `dist/assets`를 자동으로 모으므로 three 묶음은 자동으로 들어간다.
- 운영 주소는 https://materials-discovery-lab.yelsam.workers.dev/ 이다. Cloudflare Workers 정적 자산 업로드이고 `wrangler.jsonc`가 없다. 배포 절차는 `docs/reviews/RELEASE-REVIEW-20261111.md`를 따른다.

### 코스 설계표

길은 왼쪽에서 오른쪽으로 한 줄이다. 카메라는 앞쪽 위에서 따라가고 돌리지 않는다. 방향판 위쪽이 화면 안쪽이다.

|---|---|---|---|---|

- 시료를 시험하면 오른쪽에 설명 두 개가 뜨고, 맞는 설명을 고르면 `dispatch({type:'observe'})`로 기록한다. 선택지는 2D 화면과 같은 방식(`resultFor`의 결과와 반대 결과)으로 만든다.
- 틀리면 「다시 시험하기」로 같은 시료를 다시 본다. 같은 시료에서 세 번 틀리면 단단이가 볼 곳을 알려 주고 「기존 방식으로 하기」를 권한다.
- 구역을 막는 문은 없다. 순서를 바꿔도 되고 기록한 시료를 다시 시험해도 된다.
- 길 앞뒤에 난간이 있어 떨어질 곳은 없다. 그래도 높이가 -6 아래로 내려가면 마지막으로 지난 구역 입구로 돌아오게 해 둔다.
- 고무 발판은 눌렸다가 돌아오기만 한다. 캐릭터를 튕겨 올리지 않는다.

3. `src/screens/SampleRunStage.tsx`, `run-stage.css`: 화면 겹침(방향판·점프·시험 버튼·진행 칩·설명 고르기)과 규칙 연결.

7. TRD 1절 고치기, 검증, 커밋·푸시·배포, 「구현 결과」 기록.

## 구현 결과 (2026-11-17)

### 무엇이 바뀌었나

- 학생이 S03을 처음 열면 3D 시험 길이 뜬다. 지정 시료 9개를 구역 순서(누르기 → 당기기 → 비추기 → 적시기)대로 시험하고, 설명을 맞게 고르면 기존 `observe` 동작으로 `실험:시료:standard` 기록이 남는다. 완료 조건, 저장 필드, 의뢰 S03-a·b, 개념 영상 흐름은 그대로다.
- 기존 2D 화면은 그대로 남았다. 3D 화면의 「기존 방식으로 하기」와 2D 화면 위 줄의 「3D 시험 길로 하기」로 오간다. 자동재생과 「다른 재료도 시험하기」는 2D에만 있다.
- three는 3D 화면을 열 때만 불러온다(`engine` 묶음 524KB, gzip 136KB). Phaser 지도는 활동 화면에서 떠 있지 않아 두 화면이 함께 그려지지 않는다.

### 계획과 달라진 것

- 시작 카드 그림은 넣지 않았다(누를 일이 한 번 늘어난다). 대신 첫 이동 전까지 조작 안내 한 줄이 떠 있다.
- 공중에서도 바닥과 같은 마찰을 준다(참고 예제는 1/10). 달리며 뛰어도 발판을 넘어가지 않게 하려는 것이다. 발판 옆면에 발이 뜬 채 닿으면 위로 올려 주고, 착지하면 0.45초 멈춰서 눌림을 볼 수 있게 했다.
- 길 앞뒤에 보이지 않는 벽이 있어 떨어질 곳이 없다. 높이 -6 아래로 내려가면 지난 구역 입구로 돌아오는 처리는 들어 있지만, 실제로 일어나는 경로가 없어 화면에서 확인하지는 못했다(복귀 지점 계산은 단위 테스트로 확인).
- 화면 높이 500px 미만에서는 기존 화면이 먼저 열린다.
- 당기기 구역은 시료 간격을 2.8로 넓혔다(늘어난 끈과 연구원이 옆 시료와 겹쳐서).
