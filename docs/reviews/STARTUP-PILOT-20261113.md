# 물질 공방 대작전 초기 로딩 시범 적용

첫 화면은 HTML 제목과 준비 안내로 열고, 로고와 시작 버튼을 배경보다 우선한다. 기존 인트로 세 장면을 유지한다. 새 탐험의 인트로 대화 중에는 다음 화면인 지도 코드와 그 의존성만 미리 받고, 실제 지도 진입에서 같은 요청을 재사용한다. 첫 활동 코드·조작 화면은 활동에 들어갈 때 함께 요청한다.

지도 코드나 엔진, 필수 지도 그림이 실패하거나 지도가 3초 넘게 준비되지 않으면 ‘탐구부터 시작하기’와 ‘지도 다시 불러오기’를 제공한다. 대체 진입은 기존 진도에 맞는 활동으로 이어지며 관찰 기록과 해금 조건을 유지한다.

| 항목 | 일반 연결, 전 → 후 | 제한망, 전 → 후 |
|---|---:|---:|
| 첫 콘텐츠 표시 | 24 → 32 ms | 200 → 192 ms |
| 시작 버튼 준비 | 48 → 46 ms | 372 → 317 ms |
| 타이틀 로고 준비 | 49 → 46 ms | 684 → 455 ms |
| 인트로 마지막 버튼 → 지도 표시 | 418 → 136 ms | 2,280 → 2,013 ms |
| 첫 활동 열기 → 우산 관찰 버튼 준비 | 788 → 38 ms | 383 → 222 ms |

동일 작업 트리의 변경 전후 Vite 프로덕션 빌드를 Chrome 157, 1280×800에서 교대로 측정했다. 각 빌드·조건별 새 브라우저 문맥 5회 중앙값이며 브라우저 HTTP 캐시와 서비스워커를 껐다. 제한망은 다운로드 10Mbps, 지연 40ms, CPU 4배 감속이다. 인트로 첫 장면에서 1.2초 머문 뒤 남은 장면을 넘겼다. 지도 측정에 이야기를 보는 시간은 포함하지 않았다. 첫 활동은 기존 의뢰 대화에서 ‘첫 번째 활동 시작하기’를 누른 시점부터 실제 기록 버튼이 표시될 때까지다. 일반 연결에서 이전 빌드의 약 0.79초는 준비 화면 교체 대기까지 포함한 관찰값이다. 학교 태블릿과 운영 서버의 응답 시간은 포함하지 않았다.

- 정상 인트로를 모두 통과했고 지도 코드 요청은 한 번이었다. 홈에서는 지도·엔진·활동 요청이 없었고, 인트로 중에는 활동을 요청하지 않았다. 데이터 절약 모드에서는 지도도 들어갈 때 요청했다.
- 지도 모듈, Phaser, 지도 그림을 각각 막거나 지도 모듈의 응답을 지연시켰다. ‘탐구부터 시작하기’로 들어가 우산 천·살·손잡이를 각각 터치하고 기록해 3/3 상태와 저장값을 확인했다. 느린 지도 응답을 풀어도 활동을 덮지 않았다. 진행 중인 관찰 기록 한 건도 대체 진입 후 그대로였고, 활동 완료는 자동으로 추가되지 않았다.
- 915×412에서 시작 코드·지도 코드의 차단을 해제하고 각각 ‘다시 열기’와 ‘지도 다시 불러오기’로 복구했다.
- 첫 탐구 진입 뒤 오프라인 저장을 준비한다. 최종 빌드에서 연결을 끊고 새로고침해 관찰을 1/3에서 2/3으로 이어갔고, 지도와 첫 화면도 다시 열었다.
- 타입 검사, 프로덕션 빌드, 오프라인 목록 생성, 단위 검사 70개 통과. 측정 당시 빌드는 로컬 시범 빌드이며, 아래 수치는 운영 배포 성능을 뜻하지 않는다.
