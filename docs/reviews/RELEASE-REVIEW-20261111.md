## 공개 로딩과 성능

새 Chrome 프로필에서 일반 연결은 첫 화면 1.692초, 시작 버튼 1.739초였어. 10Mbps·40ms 추가 지연 조건에서는 첫 화면 2.828초, 시작 버튼 3.312초였어. 초기 전송량은 약 1.37MB였고 실행 요청은 운영 origin에만 발생했어. 지도 180프레임 측정은 평균 59.7fps, 95백분위 프레임 간격 16.7ms였어. 측정 장비는 데스크톱 headless Chromium이야. [측정값](delivery-20261111/live-loading.json)

## 납품 전에 사람이 확인할 조건

| 항목 | 현재 상태 | 확인 담당·시점 |
|---|---|---|
| 실제 iPad·Android·Safari·인앱 브라우저 | Chrome의 가로·세로 viewport로 검증, 실기 미검증 | 납품 담당자가 교실 기기로 접속할 때 |
| 교사 내용 검수와 40분 수업 | 활동별 목표·성취기준·출처·검토자 필드 구조화, needsReview=true | 담당 교사가 최종 자료 검수할 때 |
| 제공·생성 이미지 이용 근거 | 출처와 미확인 항목은 CREDITS에 보존 | 납품 담당자가 상업 이용 근거 확인 |
| 확대·최악 배경 대비·Safari 인쇄 | 글자 크기·Chromium PDF는 실측, 확대·전체 대비·실물 인쇄 미검증 | 교실 기기 최종 확인 때 |

740×360의 짧은 가로 화면에서는 제작 모형이 작고 일부 제어는 44px야. 미완성 제작 부품 선택과 시험 중간 상태는 새로고침하면 다시 시작하고, 완료한 납품과 학습 기록은 저장돼. 손상 JSON은 원문 복구본을 남기고 새 기록으로 시작해. 필드별 자동 복구는 구현 범위에 포함되지 않아.

기존에 열어 둔 게임은 모든 탭을 닫고 운영 주소를 다시 열면 새 서비스워커를 사용해. 운영과 localhost·preview의 기록은 origin별로 분리돼. 검증 보고서와 테스트 도구를 추가한 뒤 앱 소스·배포 자산이 바뀌지 않았는지 Git diff로 확인하고 함께 push했어.
